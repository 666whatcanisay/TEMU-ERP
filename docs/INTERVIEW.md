# 面试演示：三分钟讲清楚

## 开场：解决什么问题

“我先选了一条具体业务路径：全托管商品从候选研究，到供货核价，再到内部提报准备。把证据、成本、SKU和反馈集中起来，使每次判断能说明原因，资料能复用。这个项目是开发背景切入业务实操的验证，不假装已经接入公司的店铺。”

## 演示顺序

| 时间 | 展示 | 讲清楚的价值 |
|---|---|---|
| 0:00—0:40 | 候选研究：五商品基准／保守对比 | 同一口径下区分利润空间与风险，PP小盒完整成本后亏损 |
| 0:40—1:30 | 六件套：21元供货价、4.48元预算净收益 | 看采购差价不够；把风险、分摊、资金和税费一起考虑 |
| 1:30—2:00 | 鼠标移到“退款风险” | 每项概率、公式、金额和来源可追溯，假设可以被账单替换 |
| 2:00—2:30 | 商品资料及SKU编辑入口 | 新建能录入，变体独立保存，平台ID未返回就留空 |
| 2:30—3:00 | 反馈记录及内部评审单 | 核价影响对应SKU；导出带待办和明细，减少重复整理 |

## 适合回答的技术问题

数据库演示只选三个：刷新Navicat，展开“视图”，依次打开`面试01_选品证据`、`面试02_商品成本`、`面试03_买手核价`；需要逐笔费用时补看`明细_费用组成`。关系图、1分钟讲法和只读SQL见[数据库设计与面试说明](DATABASE.md)。

- **为什么不是完整ERP？** 先验证一条工作链能否用起来，避免在未了解公司现有系统时重复造工具。
- **数据库如何升级？** 第一版SQLite/通用JSON验证业务，随后升级为MySQL关系实体。商品一对多SKU、证据多对多、费用和核价关联SKU，用外键/唯一键/事务约束。迁移前备份，导入后重建旧DTO做摘要对账，逐商品比较利润。DDL和DML分阶段，旧表归档。金额与图表算法不必重写。
- **AI用在哪里？** 当前规则提取已有实现；大模型通过适配器预留，没有将“未来可接”当作“已经完成”。
- **如何保证金额可信？** Decimal、明确销售单位、四位小数对账、原始输入与确认失效机制、独立算例与测试。
- **如何证明价值？** 已证明流程、计算、保存与导出的正确性；要证明业务提效，下一步需要用真实任务比较每件资料准备时间、遗漏数与同事持续使用情况。

## 入职后的验证顺序

1. 跟运营完整走一个SKU，取得脱敏真实报价、结算账单和当前类目模板。
2. 对账承担费用、退款责任、SKU字段与买手反馈，而不是继续凭公共资料猜后台。
3. 用一个同事每天都会做的小任务试用，记录耗时、错误和重复录入。
4. 有授权后再接ERP导出或RPA填写；有可验证收益后扩展到更多类目。

所有采购价、公司门槛、扣款概率与买手反馈均需在演示时说明其案例性质。不要宣称已创造利润、已提升通过率，或能绕过买手自动上架。
